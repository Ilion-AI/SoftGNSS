1. НАЗНАЧЕНИЕ И ОБЛАСТЬ ПРИМЕНЕНИЯ
================================================================

1.1. Назначение
    Разработка программного модуля обнаружения (Acquisition)
    сигналов GPS L1 C/A в сырых I/Q отсчетах.

    Модуль должен:
    - обнаружить все видимые спутники GPS (PRN 1..32);
    - определить доплеровский сдвиг частоты каждого спутника;
    - определить фазу кода (Code Phase) каждого спутника;
    - оценить отношение сигнал/шум (SNR) для каждого
      обнаруженного спутника;
    - адаптивно определить порог обнаружения.

1.2. Область применения
    - Исследование GNSS;
    - RF-анализ и классификация сигналов;
    - Тестирование и валидация алгоритмов программных
      GNSS-приемников;
    - Обучение и исследовательская деятельность.

1.3. Источник данных
    Набор данных "Tuni2025 Datasets for GNSS - GPS Spoofing",
    опубликованный на платформе Zenodo.
    DOI: 10.5281/zenodo.17249795
    Лицензия: CC BY 4.0

3. ТРЕБОВАНИЯ К АЛГОРИТМУ ОБНАРУЖЕНИЯ
================================================================

3.1. Метод поиска

    Использовать алгоритм Parallel Code Phase Search
    (параллельный поиск по фазе кода с использованием БПФ).

    Суть алгоритма:
    1) Входной сигнал длиной 1 мс (по умолчанию) умножается
       на опорную несущую с пробной доплеровской частотой fd.
    2) Результат умножения преобразуется в частотную область
       с помощью БПФ (FFT).
    3) Спектр умножается поэлементно на комплексно-сопряженный
       спектр локальной копии PRN-кода.
    4) Результат преобразуется обратно во временную область
       с помощью обратного БПФ (IFFT).
    5) Модуль результата дает корреляционную функцию для
       данной пробной частоты fd.
    6) Процедура повторяется для всех пробных частот
       в заданном диапазоне.

    Обоснование: прямой перебор во временной области при
    fs = 50 МГц неприемлемо медленный. FFT-метод сводит
    сложность поиска по фазе кода от O(N^2) к O(N*log(N)).

3.2. Пространство поиска

    3.2.1. Измерение 1: Доплеровская частота
        Диапазон: от -10 000 Гц до +10 000 Гц
        Шаг поиска (по умолчанию): 500 Гц
        Количество пробных частот: 41
        Параметр шага задается пользователем.

    3.2.2. Измерение 2: Фаза кода (Code Phase)
        Диапазон: от 0 до (fs * 0.001 - 1) отсчетов
        При fs = 50 МГц: от 0 до 49 999 отсчетов
        Разрешение: 1 отсчет (определяется fs)
        Поиск выполняется автоматически через FFT
        (все фазы проверяются одновременно).

3.3. Номера спутников для поиска

    Диапазон PRN: от 1 до 32 включительно.
    Пользователь может ограничить набор PRN через
    параметр командной строки.
    По умолчанию: поиск по всем 32 PRN.

3.4. Генерация локальных PRN-кодов

    Модуль должен программно генерировать C/A коды GPS
    для PRN 1..32 с использованием стандартного алгоритма
    на основе двух LFSR (G1, G2) согласно IS-GPS-200.

    Генератор должен выдавать последовательность из 1023
    чипов для каждого PRN.

    Сгенерированный код должен быть передискретизирован
    (upsampled) до частоты дискретизации fs входного
    сигнала. При fs = 50 МГц один период кода содержит
    50 000 отсчетов.

3.5. Время когерентного накопления

    3.5.1. Значение по умолчанию: 1 мс (один период
        PRN-кода GPS C/A).

    3.5.2. Значение задается параметрически через
        командную строку. Допустимые значения: 1..20 мс.
        При значениях > 1 мс необходимо учитывать
        возможную инверсию фазы из-за бит навигационного
        сообщения (граница бита каждые 20 мс).

    3.5.3. Некогерентное накопление (опционально):
        Пользователь может задать количество некогерентных
        суммирований. По умолчанию: 1 (без накопления).
        При некогерентном суммировании суммируются модули
        (или квадраты модулей) нескольких последовательных
        когерентных корреляций.

3.6. Адаптивный порог обнаружения

    3.6.1. Метод определения порога

        Порог обнаружения НЕ задается фиксированным числом.
        Вместо этого для каждого PRN и каждой пробной
        частоты fd порог определяется адаптивно на основе
        статистики корреляционной матрицы.

        Алгоритм определения порога:
        1) Для текущего PRN и fd вычислить корреляционную
           функцию C(tau) для всех фаз кода tau.
        2) Найти максимальный пик: peak = max(|C(tau)|).
        3) Исключить область вокруг пика (+/- K отсчетов,
           где K рекомендуется равным количеству отсчетов
           на 1 чип, то есть fs / 1.023e6).
        4) Вычислить среднее (mean) и стандартное
           отклонение (std) оставшихся значений |C(tau)|
           (это оценка уровня шума).
        5) Вычислить метрику SNR:
           SNR = (peak - mean) / std

    3.6.2. Критерий обнаружения

        Спутник считается обнаруженным, если:
        SNR >= threshold

        Значение threshold по умолчанию: 2.5
        Пользователь может задать threshold через
        параметр командной строки.

        Рекомендуемые значения:
        - 2.0 .. 2.5 : высокая чувствительность,
          возможны ложные обнаружения;
        - 2.5 .. 3.5 : стандартный режим;
        - 3.5 .. 5.0 : консервативный режим,
          только надежные обнаружения.

    3.6.3. Дополнительная метрика (опционально)

        Вычислить отношение первого пика ко второму
        наибольшему пику:
        ratio = peak_1 / peak_2

        Если ratio < 1.5, результат считается
        ненадежным и помечается флагом "weak".

3.7. Вычисление точной фазы кода

    3.7.1. Грубая оценка
        Индекс максимума корреляционной функции дает
        фазу кода с точностью до 1 отсчета:
        code_phase_samples = argmax(|C(tau)|)

    3.7.2. Перевод в единицы измерения
        Результат должен быть представлен в:
        - отсчетах (samples);
        - чипах: code_phase_chips =
          code_phase_samples * 1.023e6 / fs;
        - метрах: code_phase_m =
          code_phase_chips * (c / 1.023e6),
          где c = 299 792 458 м/с.

    3.7.3. Уточнение (опционально)
        Для повышения точности может применяться
        параболическая интерполяция по трем точкам
        вокруг максимума корреляции.

4. ТРЕБОВАНИЯ К РЕЖИМУ РАБОТЫ
================================================================

4.1. Рабочий режим

    4.1.1. Описание
        Основной режим. Обнаружитель читает данные
        непосредственно из бинарного .bin файла.

    4.1.2. Чтение больших файлов
        Файл может иметь размер до 30 ГБ и более.
        ЗАПРЕЩАЕТСЯ загружать весь файл в оперативную
        память целиком.

        Требования к чтению:
        a) Использовать потоковое (chunked) чтение.
           Размер блока чтения задается параметрически.
           По умолчанию: 1 000 000 комплексных отсчетов
           (8 000 000 байт = ~7.6 МБ).
        b) Чтение выполняется строго по границам
           комплексных пар (кратно 8 байтам).
        c) Для алгоритма Acquisition необходим фрагмент
           длиной не менее T_coh (время когерентного
           накопления). При T_coh = 1 мс и fs = 50 МГц
           минимальный блок = 50 000 комплексных отсчетов
           (400 000 байт).
        d) Рекомендуется использовать numpy.memmap или
           numpy.fromfile с параметрами offset и count
           для чтения произвольных фрагментов файла
           без загрузки всего файла.

    4.1.3. Обработка нескольких блоков
        Пользователь задает, сколько блоков (миллисекунд)
        обработать. По умолчанию: 1 блок (1 мс).
        Если задано несколько блоков, результаты обнаружения
        по каждому блоку выводятся отдельно, затем
        формируется сводная таблица.

    4.1.4. Смещение от начала файла
        Пользователь может задать начальное смещение
        в комплексных отсчетах (не в байтах).
        По умолчанию: 0 (с начала файла).

4.2. Автоматическое определение параметров из JSON

    4.2.1. При запуске модуль должен:
        a) Прочитать JSON файл (Info_about_dataset.json).
        b) Извлечь из поля metadata.description:
           - частоту дискретизации (regexp: "XX MSps");
           - формат данных ("interleaved 32-bit float");
           - тип сигнала ("GPS L1").
        c) Извлечь из files.entries:
           - имя .bin файла;
           - размер .bin файла (для валидации).
        d) Если автоматическое извлечение не удалось,
           выдать предупреждение и запросить параметры
           через командную строку.

5. ТРЕБОВАНИЯ К ВЫХОДНЫМ ДАННЫМ

5.1. Таблица обнаруженных спутников

    Для каждого обнаруженного спутника вывести:

    +-----+----------+------------+-------------+-------+------+
    | PRN | Doppler  | Code Phase | Code Phase  | SNR   | Flag |
    |     | (Hz)     | (samples)  | (chips)     |       |      |
    +-----+----------+------------+-------------+-------+------+
    |  3  | -2500.0  |   12345    |   253.12    | 14.2  |  ok  |
    |  6  |  1000.0  |   34567    |   708.32    |  8.7  |  ok  |
    | 14  |   500.0  |   45678    |   935.87    |  2.8  | weak |
    +-----+----------+------------+-------------+-------+------+

    Столбцы:
    - PRN: номер спутника (1..32)
    - Doppler (Hz): оценка доплеровского сдвига
    - Code Phase (samples): фаза кода в отсчетах
    - Code Phase (chips): фаза кода в чипах
    - SNR: отношение сигнал/шум (метрика из п.3.6)
    - Flag: "ok" | "weak" (см. п.3.6.3)

5.2. Сводная информация

    Помимо таблицы, вывести:
    - Общее количество обнаруженных спутников
    - Количество надежных обнаружений (flag = "ok")
    - Количество слабых обнаружений (flag = "weak")
    - Использованные параметры поиска (fs, диапазон
      Доплера, шаг, время интеграции, порог)
    - Время выполнения поиска (в секундах)

5.3. Файловый вывод

    5.3.1. Результаты должны сохраняться в JSON файл.
        Имя файла: <входной_файл>_acquisition_results.json

    5.3.2. Структура JSON результатов:
        {
          "input_file": "...",
          "mode": "bin",
          "parameters": {
            "fs": ...,
            "f_if": ...,

          },
          "satellites": [
            {
              "prn": ...,
              "doppler_hz": ...,
              "code_phase_samples": ...,

            },

          ],

    5.3.3. Опционально: сохранение корреляционных матриц

5.4. Визуализация (опционально)

    Для каждого обнаруженного спутника построить:
    - 2D-карту корреляции (Doppler x Code Phase);
    - 1D-срез корреляции по фазе кода для найденного

    - 1D-срез корреляции по Доплеру для найденной
      фазы кода.
    Графики сохраняются в формате PNG.

6. ТРЕБОВАНИЯ К ПРОИЗВОДИТЕЛЬНОСТИ И ПАМЯТИ
================================================================

6.1. Оперативная память
    Потребление RAM не должно превышать 2 ГБ при работе
    с файлами любого размера (включая 30 ГБ .bin).

    Для справки: при fs = 50 МГц один блок 1 мс
    занимает 50 000 complex64 = 400 КБ.
    FFT-буферы для Parallel Code Phase Search
    потребуют ~3-5 таких блоков одновременно = ~2 МБ.
    32 PRN-кода: 32 * 400 КБ = ~12.5 МБ.
    Итого рабочий набор: менее 50 МБ.

6.2. Время обработки
    Обнаружение по всем 32 PRN для одного блока 1 мс
    (41 частота Доплера) не должно превышать 30 секунд
    на типичном ПК (4-ядерный CPU, 3 ГГц).

    Рекомендации по оптимизации:
    - Использовать numpy.fft (или scipy.fft) для FFT;
    - Предварительно вычислить и кешировать FFT всех
      32 PRN-кодов (они не меняются между блоками);
    - По возможности использовать векторизированные
      операции numpy вместо циклов Python.

6.3. Масштабируемость
    Архитектура должна позволять в будущем добавить
    многопоточную обработку PRN (каждый PRN независим).

================================================================
7. ТРЕБОВАНИЯ К ДИАГНОСТИКЕ И ПРЕДУПРЕЖДЕНИЯМ
================================================================

7.1. Проверка достаточности данных

    При запуске модуль обязан проверить:
    a) Размер входного файла (bin)
    b) Вычислить количество доступных комплексных
       отсчетов.
    c) Вычислить доступную длительность записи:
       duration = num_samples / fs
    d) Сравнить с запрошенным временем когерентного
       накопления (T_coh).

    Если duration < T_coh:
       Выдать ПРЕДУПРЕЖДЕНИЕ:
       "ВНИМАНИЕ: длительность данных ({duration:.4f} с)
       меньше запрошенного времени когерентного накопления
       ({T_coh} мс). Обнаружение невозможно."
       Завершить работу с кодом ошибки.

    Если duration < T_coh * N_noncoherent:
       Выдать ПРЕДУПРЕЖДЕНИЕ:
       "ВНИМАНИЕ: данных недостаточно для {N_noncoherent}
       некогерентных суммирований."

    Если duration >= T_coh, но меньше 10 мс:
       Выдать информационное сообщение:
       "ИНФОРМАЦИЯ: доступно {duration:.4f} с данных.
       Рекомендуется использовать >= 10 мс для надежного
       обнаружения."

7.2. Проверка целостности BIN файла

    a) Размер файла должен быть кратен 8 байтам
       (полные IQ-пары). Если не кратен, выдать
       предупреждение и обрезать хвост.
    b) Размер файла из JSON (если доступен) должен
       совпадать с реальным размером файла на диске.
       Если не совпадает, выдать предупреждение
       (файл мог быть обрезан или поврежден).

7.3. Проверка данных на валидность

    При чтении каждого блока проверять наличие
    NaN и Inf значений.

    Если обнаружены:
    a) Подсчитать количество невалидных IQ-пар.
    b) Вывести предупреждение с указанием процента
       невалидных данных.
    c) Заменить невалидные IQ-пары на (0.0, 0.0).
    d) Если процент невалидных данных > 10%,
       выдать ошибку и прекратить обработку данного
       блока.

7.4. Уровень логирования

    Модуль должен поддерживать уровни логирования:
    - ERROR: только ошибки
    - WARNING: ошибки + предупреждения
    - INFO: + информационные сообщения (по умолчанию)
    - DEBUG: + отладочная информация (значения
      корреляции, промежуточные результаты)

    Уровень задается через параметр --log-level.

8. ТРЕБОВАНИЯ К СТРУКТУРЕ КОДА
================================================================

8.1. Модульная архитектура

    Код должен быть разбит на следующие модули:

    8.1.1. metadata_parser.py
        Назначение: чтение JSON, извлечение параметров.
        Функции:
        - parse_zenodo_json(path) -> dict
          Возвращает словарь с параметрами:
          fs, bin_name, bin_size, signal_type, format_type

    8.1.2. data_loader.py
        Назначение: унифицированная загрузка данных
        из BIN.
        Функции:
        - load_bin_chunk(path, offset, num_samples, dtype)
            -> np.ndarray (complex64)
        - validate_chunk(data) -> (clean_data, stats)
          Проверка NaN/Inf, замена, статистика.

    8.1.3. prn_generator.py
        Назначение: генерация C/A кодов GPS.
        Функции:
        - generate_ca_code(prn) -> np.ndarray (1023 чипа)
        - resample_code(code, fs, code_freq)
            -> np.ndarray (длина = fs * 0.001)

    8.1.4. acquisition.py
        Назначение: алгоритм обнаружения.
        Функции:
        - acquire_single_prn(signal, code_fft, fs, 
            doppler_range, doppler_step)
            -> AcquisitionResult
        - acquire_all_prn(signal, fs, prn_list, ...)
            -> list[AcquisitionResult]

    8.1.5. detection.py
        Назначение: адаптивный порог и принятие решения.
        Функции:
        - compute_snr(correlation) -> float
        - detect(result, threshold) -> bool

    8.1.6. output_formatter.py
        Назначение: форматирование и сохранение результатов.
        Функции:
        - print_table(results)
        - save_json(results, path)
        - plot_correlation(result, path) [опционально]

    8.1.7. main.py
        Назначение: точка входа, CLI-интерфейс,
        оркестрация вызовов.

8.2. Интерфейс командной строки (CLI)

    Параметры запуска:

    Обязательные:
    --data <путь>       Путь к файлу данных (.bin)

    Опциональные:
    --json <путь>       Путь к JSON метаданных
                        (по умолчанию: 17249795.json)
    --fs <число>        Частота дискретизации, Гц
                        (если не извлечена из JSON)
    --doppler-range <число>
                        Диапазон Доплера, Гц
                        (по умолчанию: 10000)
    --doppler-step <число>
                        Шаг Доплера, Гц
                        (по умолчанию: 500)
    --coherent-ms <число>
                        Время когерентного накопления, мс
                        (по умолчанию: 1)
    --noncoherent <число>
                        Количество некогерентных суммирований
                        (по умолчанию: 1)
    --threshold <число> Порог SNR для обнаружения
                        (по умолчанию: 2.5)
    --prn <список>      Список PRN через запятую
                        (по умолчанию: 1-32)
    --offset <число>    Начальный отсчет в файле
                        (по умолчанию: 0)
    --blocks <число>    Количество блоков для обработки
                        (по умолчанию: 1)
    --output <путь>     Путь к выходному JSON
    --log-level <уровень>
                        ERROR|WARNING|INFO|DEBUG
                        (по умолчанию: INFO)

    Пример запуска (рабочий режим):
    python main.py --json 17249795.json \
        --data signal.bin \
        --doppler-range 10000 \
        --threshold 2.5

    Пример запуска (тестовый режим):
    python main.py --json 17249795.json \
        --data test_data.bin

        - Результат сохраняется в JSON.

    9.2.2. Тест согласованности:
        - При запуске на одних и тех же данных
          из .bin результаты обнаружения
          ДОЛЖНЫ совпадать (те же PRN, Doppler,
          Code Phase).

        - При подаче файла с искусственно вставленными

10. ОГРАНИЧЕНИЯ И ДОПУЩЕНИЯ
================================================================

10.1. Поддерживается ТОЛЬКО сигнал GPS L1 C/A.
      Другие системы (ГЛОНАСС, Galileo, BeiDou)
      и другие частоты (L2, L5) не поддерживаются
      в текущей версии.

10.2. Алгоритм выполняет ТОЛЬКО этап обнаружения
      (Acquisition). Этапы слежения (Tracking),
      демодуляции навигационного сообщения и
      вычисления координат пользователя НЕ входят
      в объем данного ТЗ.

10.3. Предполагается, что промежуточная частота
      (IF) = 0 Гц (Baseband I/Q). Если IF != 0,
      пользователь должен задать ее явно через
      дополнительный параметр (в текущей версии
      не реализовано).

10.4. Предполагается Little-Endian порядок байт
      для .bin файлов.

10.5. Алгоритм работает в однопоточном режиме.
      Многопоточность может быть добавлена в
      будущих версиях.

12. ГЛОССАРИЙ
================================================================

Acquisition - Обнаружение (захват) спутникового сигнала.
              Первый этап обработки в программном
              GNSS-приемнике.

C/A код     - Coarse/Acquisition code. Псевдослучайная
              последовательность длиной 1023 чипа,
              уникальная для каждого спутника GPS.

CDMA        - Code Division Multiple Access. Метод
              множественного доступа с кодовым
              разделением каналов.

Chipping Rate - Скорость передачи чипов C/A кода.
              Для GPS: 1.023 МГц.

Code Phase  - Фаза кода. Временная задержка начала
              PRN-кода относительно начала записи.

Doppler     - Доплеровский сдвиг частоты, вызванный
              относительным движением спутника
              и приемника.

FFT         - Fast Fourier Transform (быстрое
              преобразование Фурье).

GNSS        - Global Navigation Satellite System.

GPS         - Global Positioning System (USA).

I/Q         - In-phase / Quadrature. Синфазная и
              квадратурная составляющие комплексного
              сигнала.

IF          - Intermediate Frequency (промежуточная
              частота).

IFFT        - Inverse FFT (обратное БПФ).

LFSR        - Linear Feedback Shift Register (линейный
              регистр сдвига с обратной связью).

PRN         - Pseudo-Random Noise. Номер псевдослучайной
              последовательности (идентификатор спутника).

SDR         - Software Defined Radio (программно
              определяемое радио).

SNR         - Signal-to-Noise Ratio (отношение
              сигнал/шум).

Spoofing    - Подмена (имитация) спутникового сигнала
              с целью ввести приемник в заблуждение.

USRP        - Universal Software Radio Peripheral
              (аппаратная платформа SDR).
